Neden değişti

JSON'da her mesaj "voltage_plausibility_checked" gibi key'leri string olarak tekrar tekrar taşıyor; hücresel hatta asıl veriden çok bu isimler gidiyor. Yeni biçimde her JSON key'i tek bir enum'daki (msg_field_t) 1 baytlık bir koda karşılık geliyor, her alanın kaç bayt olduğu bir boy tablosunda duruyor ve paketin son 2 baytı CRC.

Backend'den beklenenler

  1. +/bin topic'ine abone olun. Yeni firmware'li cihazlar tüm mesajlarını Meven:<MAC>/bin'e binary basar.
  2. Her paketi doğrulayın. İlk bayt versiyon (0x01), son 2 bayt CRC. Uymayan paketi atın, loglayın ve sayaç artırın.
  3. Alanları boy tablosuyla çözün. Tabloda olmayan bir alan gelirse paketin tamamını atın ve alarm üretin: cihaz backend'den daha yeni bir tablo kullanıyor demektir.
  4. JSON köprüsü: çözülen mesajı bugünkü JSON'un aynısına çevirip eski topic'lere basın. HEALTH → Meven:<MAC>/health, diğerleri → Meven:<MAC>/data. Dashboard hiçbir şey değiştirmeden çalışmaya devam eder. Bu işi scripts/mqtt_bridge.py yapar; sunucuda 7/24 çalışması yeterli (python scripts/mqtt_bridge.py, broker bilgisi MQTT_URI, MQTT_USERNAME, MQTT_PASSWORD ortam değişkenlerinden). Kendi dilinizde yazmak isterseniz kurallar aşağıda.
  5. Health'in sabit alanlarını saklayın. idf_version, build_date, build_time ve thread.network_name her MQTT bağlantısında yalnızca bir kez gelir. Cihaz başına son değeri saklayıp her health JSON'una ekleyin.
  6. Sıraya uyun. Köprü çalışmadan hiçbir cihaza yeni firmware OTA'sı gönderilmemeli; yoksa dashboard o cihazın verisini göremez.
  7. İsteğe bağlı: komutları binary göndermeye geçin. Cihaz geçiş döneminde JSON komutları da kabul eder.

Paket biçimi ve CRC

Örnek: kanal 0'daki lambayı %25'e çeken dim komutu, id 7.

14 bayt; aynı komut JSON'da 46 bayt. Amber baytlar alan kodu, yanındakiler değer.

  • Bayt 0 protokol versiyonu, şu an 0x01.
  • İlk alan her zaman MSG_FIELD_TYPE (0x01); değeri mesaj tipidir.
  • Ardından istenen sırada [alan kodu][değer] çiftleri gelir. Değerin boyu boy tablosundan okunur (1–4 bayt, little-endian). i8 alanlar ikiye tümleyendir.
  • Değişken boylu alan (metin, bayt dizisi, liste): önce 1 bayt uzunluk (0–255), sonra veri. Metin UTF-8/ASCII, NUL yok.
  • Değeri olmayan alan pakete hiç yazılmaz. JSON'daki null bundan gelir.
  • Son 2 bayt paketin geri kalanının (versiyon dahil, CRC hariç) CRC'si, önce alt bayt.
CRC parametresiDeğer
polinom0x1021
başlangıç0xFFFF

Python

import binascii
crc = binascii.crc_hqx(data, 0xFFFF)

JavaScript / TypeScript

function crc16(bytes) {
  let crc = 0xffff;
  for (const b of bytes) {
    crc ^= b << 8;
    for (let i = 0; i < 8; i++)
      crc = crc & 0x8000
        ? ((crc << 1) ^ 0x1021) & 0xffff
        : (crc << 1) & 0xffff;
  }
  return crc;
}

Çözme algoritması

paket boyu < 5                        → reddet (TOO_SHORT)
paket[0] != 0x01                      → reddet (VERSION)
crc = paket[son 2 bayt], little-endian
crc != CRC16(paket[0 .. son-2])       → reddet (CRC)

i = 1
while i < boy - 2:
    alan = paket[i];  i += 1
    n = BOY_TABLOSU[alan]
    n tanımsız                        → reddet (FIELD)
    n == değişken:
        n = paket[i];  i += 1
    i + n > boy - 2                   → reddet (TRUNCATED)
    değer = paket[i .. i + n];  i += n

ilk alan TYPE değil                   → reddet (NO_TYPE)

Paketin tamamı doğrulanmadan hiçbir alan kullanılmamalı. Aynı alan bir pakette birden fazla geçebilir; bu yalnızca health'teki komşu listesinde olur.

Versiyon ve derleme zamanı

  • Versiyonlar (HEALTH_FIRMWARE_VERSION, HEALTH_IDF_VERSION, OTA_LAST_TARGET_VERSION): major << 16 | minor << 8 | patch, her parça 0–255. JSON metni firmware ve hedef versiyon için "1.0.25" (0x010019); IDF için başına v eklenir, patch 0 ise yazılmaz (0x060000 → "v6.0").
  • Derleme zamanı (HEALTH_BUILD_TIMESTAMP): __DATE__ + __TIME__ değerinin Unix saniyesi (saat dilimi yok, UTC gibi okunur). JSON'da build_date C __DATE__ biçiminde ("Nov 2 2026", gün 2 haneye boşluklu), build_time "HH:MM:SS".
  • Periyodik health'te metin alan yoktur; tek metin olan ağ adı bağlantı başına bir kez gelir.

JSON'a çevirme kuralları

Köprü, dashboard'un bugün aldığı JSON'un aynısını üretmeli. Pakette yalnızca ham değerler ve cihazın kararları var; birim, ölçeklenmiş değer, durum metinleri gibi key'ler aşağıdaki kurallarla hesaplanıyor.

Maskeli değer, sayaç ve hata kuralları

Maskeli değer: u8 için 0xFE/0xFF, u16 için 0xFFFE/0xFFFF, u32 için 0xFFFFFFFE/0xFFFFFFFF. …E = temporary_unavailable, …F = unavailable.

Sayaç (operating_time_s u32, startup_count u24), N = key
≤ 0x…FDN: değer
= 0x…FDayrıca N_saturated: true
= 0x…FEN: null, N_status: "temporary_unavailable"
= 0x…FFN: null, N_status: "unavailable"
Hata bayrağı ve sayacı (ayrı alanlar), N = key
bayrak 0/1N: değer
bayrak 0xFE / 0xFFN: null, N_status: "temporary_unavailable" / "unavailable"
bayrak diğerN: null, N_status: "invalid"
sayaç ≤ 0xFCN_count: değer
sayaç 0xFDN_count: 253, N_count_saturated: true, N_count_text: "253+"
sayaç 0xFE / 0xFFN_count: null, N_count_status buna göre

Ölçek: scale_raw geçerliyse (≤ 0x06 veya ≥ 0xFA) üs, baytın işaretli 8 bit hâlidir (0xFF → −1). Değer = ham × 10üs.

Enerji, güç, yük gücü

  • Enerji ham = ENERGY_RAW_HIGH << 32 | ENERGY_RAW_LOW (48 bit). energy.raw_integer bu değerin ondalık string'i (48 bit JSON number'a güvenle sığmaz); power.raw_integer number.
  • scale_raw ölçek baytı; scale_exponent ölçek geçerliyse üs, değilse null. Ölçek geçersizse value: null, status: "invalid_scale".
  • Enerji 0xFFFFFFFFFFFE/…FF (güç 0xFFFFFFFE/…FF) → value: null, status buna göre. Diğer durumda value = ham × 10üs; ham …FD ise ayrıca saturated: true, value_is_lower_bound: true.
  • unit: enerji "Wh", güç "W"; yalnızca tek bank okumasında bank 203 için "VAh"/"VA".
  • load_power yalnızca LOAD_POWER_RAW varsa yazılır: value = ham × 10üs, unit: "W". LOAD_POWER_CHECK 0 → plausibility_checked: false, plausible: null; 1 → true, true; 2 → true, false ve implausibility_reason: "led_voltage_current_mismatch"; 3 → true, null.

Mesaj iskeletleri

  • d4i_periodic: type, address, online; status nesnesinde 8 durum key'i (eksikse null); d4i_supported; d4i nesnesinde energy, power, load_power, driver, led, sample_coherent, sample_state, sample_status, bank_206_length, bank_206_version. read_errors/decode_errors yalnızca alan varsa. Çevrimdışı: online: false, error: "no_response". Eski JSON'daki d4i.bank_206_raw_hex kaldırıldı; ham bank gerekirse d4i_read ile istenir.
  • dali_status: type, address ve 8 durum key'i üst seviyede (eksikse null).
  • d4i (tek bank): type, address, bank, ok; okunduysa length, raw_hex (büyük harf hex) ve bankın çözülmüş nesneleri; 205/206 için decode_ok ve gerekirse decode_error. Hata varyantı: ok: false, error, last_bank.
  • commission_result: type, trigger, count, addresses, rechecked, rx_idle_level, rx_idle_changed (bool), duration_ms.
  • Komut ack'i (type yok): {"action":"dim","id":7,"status":"ok"} veya {"action":"efekt","id":8,"status":"error","error":"…"}; action ve id yalnızca pakette varsa.
  • HELLO: /data'ya JSON değil, düz data metni.
  • health: device_id pakette yok, topic'teki Meven:<MAC> kullanılır. idf_version, build_date, build_time ve thread.network_name bağlantı başına bir kez gelir; köprü cihaz başına son değeri saklayıp her health'e ekler. thread.neighbors her zaman dizi; her NEIGHBOR_RLOC16 yeni eleman başlatır, sonraki NEIGHBOR_* alanları o elemana ait. NEIGHBOR_IS_CHILD → role: "child"/"router". Komşular paketin sonunda ve 512 baytlık pakete sığdığı kadar (yaklaşık 16 komşu) gider. parent_rssi_* ve parent_link_quality_* yoksa null. 0/1 alanlar bool olur.

Komutlar (sunucu → cihaz)

Mesaj tipi COMMAND (0x08). COMMAND_ID isteğe bağlı (1–65535), ack'te aynen döner; 0 ya da yok = id yok. COMMAND_CHANNEL yoksa broadcast (255).

d4i_readCOMMAND_ACTION=3, COMMAND_CHANNEL (0–63)COMMAND_ID

  • Dim yüzdesi: 0 kapalı, 1 lambanın minimumu, 100 maksimumu; cihaz kendi aralığına ölçekler.
  • Cihaz her komuta Meven:<MAC>/bin'e COMMAND_ACK ile cevap verir. CRC veya biçim hatalı pakette action/id güvenilir olmadığından ack'te yalnızca sonuç (-15/-16/-17) bulunur ve komut uygulanmaz.
  • Tipi COMMAND olmayan paket -17 alır. COMMAND_ACTION yoksa -2, bilinmeyen değerse -5.
  • Komutla ilgisi olmayan ama tabloda tanımlı alanlar yok sayılır. COMMAND_EFFECT_TEXT 32 karakterden uzunsa ilk 32'si kullanılır.
  • Geçiş dönemi: cihaz aynı topic'lerde eski JSON komutlarını da kabul eder ve onlara bugünkü gibi /data'ya JSON ack döner. İlk bayt 0x01–0x1F ise binary, { ise JSON. Binary'de id sayıdır; JSON'daki string id binary'de yoktur.

Devreye alma ve uyumluluk

  1. Backend köprüyü çalıştırır (+/bin → JSON). Eski cihazlar etkilenmez.
  2. Tek test cihazına yeni firmware yüklenir; dashboard'da verinin aynen göründüğü doğrulanır.
  3. Filoya kademeli OTA.
  4. İsteğe bağlı: dashboard/backend komutları binary göndermeye geçer.
  5. Tüm filo yeni firmware'deyken cihazdaki JSON komut desteği kaldırılabilir (ayrı sürüm, önceden haber verilir).
  • Mevcut bir alan kodunun, boyunun veya anlamının değiştirilmesi yasak.
  • Yeni alan ilgili grubun boş koduna eklenir. Backend tablosu önce güncellenir, sonra firmware OTA'sı yapılır; aksi hâlde backend tanımsız alanı görüp paketi reddeder.
  • Biçim değişirse (boy kuralı, CRC, başlık) versiyon baytı artırılır.
  • Enum'lara yalnızca yeni değer eklenir; bilinmeyen enum değeri gelirse "unknown" yazılıp loglanır, paket reddedilmez.
